Types of Schedules

A schedule is the chronological order in which the operations of several concurrent transactions are executed. The goal of concurrency control is to allow only schedules that are both serializable (correct) and recoverable (safe after failure).

Basic classification

Serial schedule
Transactions run one after another with no interleaving. Always correct, but no concurrency.
Non-serial schedule
Operations of different transactions are interleaved. Higher throughput, but may be incorrect.
Serializable schedule
A non-serial schedule whose effect is equivalent to some serial schedule of the same transactions — the correctness criterion.

Serializability

Conflicting operations
Two operations conflict if they belong to different transactions, act on the same data item, and at least one is a write (W-W, R-W, W-R).
Conflict serializable
Can be transformed into a serial schedule by swapping only non-conflicting adjacent operations. Test: the precedence (serialization) graph has no cycle.
View serializable
Equivalent to a serial schedule in terms of initial reads, final writes, and "reads-from" relationships. Every conflict-serializable schedule is view-serializable; the extra view-serializable ones contain blind writes.

Recoverability classes

ClassRuleGuarantees
RecoverableA transaction commits only after every transaction it read from has committedNo committed transaction depends on a later-aborted one
Cascadeless (ACA)A transaction may read a value only after the transaction that wrote it has committedAborting one transaction never forces others to abort
StrictNo transaction may read or write an item until the last transaction to write it has committed/abortedSimple undo using before-images; basis of Strict 2PL

Example — precedence graph test

Schedule S:  R1(A)  W1(A)  R2(A)  W2(A)  R1(B)  W1(B)  R2(B)  W2(B)

Conflicts:  W1(A)->R2(A) , W1(A)->W2(A)   => edge T1 -> T2
            W1(B)->R2(B) , W1(B)->W2(B)   => edge T1 -> T2
Precedence graph:  T1 --> T2      (no cycle)  =>  CONFLICT SERIALIZABLE
Equivalent serial order:  T1 , T2

Schedule S2: R1(A) R2(A) W1(A) W2(A)
Edges:  R2(A)->W1(A): T2->T1    R1(A)->W2(A): T1->T2
Graph has cycle T1<->T2  =>  NOT conflict serializable
Common exam traps

Conflict serializable ⟹ view serializable, but not the reverse. A schedule can be serializable yet not recoverable, and recoverable yet not serializable — the two properties are independent. Two reads never conflict. The precedence-graph test proves conflict-serializability; a cycle means "not conflict serializable" (it might still be view serializable).

Practice MCQs

Q1. A schedule is conflict serializable if and only if its precedence (serialization) graph:

  1. Contains at least one cycle
  2. Is acyclic (contains no cycle)
  3. Is a complete graph
  4. Has exactly one node
Show answer

Answer: B. An acyclic precedence graph can be topologically sorted, and that order is an equivalent serial schedule; a cycle means no consistent serial order exists.

Q2. Two operations conflict when they are from different transactions, access the same item, and:

  1. Both are reads
  2. At least one is a write
  3. Both belong to committed transactions
  4. They occur in the same block
Show answer

Answer: B. Read–read does not conflict; read–write, write–read and write–write do, because their relative order changes the outcome.

Q3. A schedule in which a transaction can read a data item only after the transaction that last wrote it has committed is called:

  1. Recoverable schedule
  2. Cascadeless schedule
  3. Serial schedule
  4. View serializable schedule
Show answer

Answer: B — Cascadeless (ACA). Because no transaction ever reads uncommitted data, aborting one transaction can never cascade into aborting others.

Q4. Which is TRUE about view serializability?

  1. Every view-serializable schedule is conflict serializable
  2. Every conflict-serializable schedule is view serializable
  3. View serializability is easy to test in polynomial time
  4. View serializable schedules cannot contain blind writes
Show answer

Answer: B. Conflict serializability is the stricter condition, so it implies view serializability. The reverse fails for schedules with blind writes, and testing view serializability is NP-hard.

Q5. In a schedule, T2 reads a value written by T1, and T2 commits before T1 commits. This schedule is:

  1. Strict
  2. Cascadeless
  3. Non-recoverable
  4. Serial
Show answer

Answer: C — Non-recoverable. If T1 later aborts, T2 has already committed based on data that never existed, and a committed transaction cannot be undone.

Q6. A serial schedule of n transactions is:

  1. Always incorrect
  2. Always serializable and recoverable
  3. Never strict
  4. Only allowed with two transactions
Show answer

Answer: B. Running transactions one at a time with no interleaving is correct by definition and is also strict (hence cascadeless and recoverable); it simply offers no concurrency.
