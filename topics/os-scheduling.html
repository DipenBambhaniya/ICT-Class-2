CPU Scheduling

The short-term scheduler picks which ready process runs next, trading off throughput, turnaround, waiting time, response time and fairness. No single algorithm is best for every workload.

Key points

FCFS
Non-preemptive, by arrival. Simple but the convoy effect (short jobs stuck behind a long one) hurts average wait.
SJF / SRTF
Shortest (remaining) job first — provably minimises average waiting time, but needs burst prediction and can starve long jobs. SRTF is the preemptive version.
Round Robin
Each ready process gets a fixed quantum in turn (preemptive). Great response time; small quantum ⇒ switch overhead, large quantum ⇒ FCFS.
Priority + aging
Run the highest priority; aging raises a waiting process's priority to prevent starvation.
Multilevel feedback queue
Multiple queues; CPU-heavy processes sink to lower-priority long-quantum queues, interactive ones stay high — approximates SJF without knowing bursts. (Real-time: RMS by period, EDF by deadline.)

Example

Jobs (all arrive t=0):  P1=6  P2=8  P3=7  P4=3

FCFS order P1,P2,P3,P4:  waits = 0, 6, 14, 21  →  avg = 10.25
SJF  order P4,P1,P3,P2:  waits = 0, 3,  9, 16  →  avg = 7.0

RR quantum 4:  P1 P2 P3 P4 | P1 P2 P3 | P2 P3 | ...  (better response, more switches)
Common exam traps

SJF minimises AVERAGE waiting time but can starve long jobs and needs burst prediction. RR quantum too small ⇒ context-switch overhead; too large ⇒ becomes FCFS. The convoy effect is an FCFS problem. RMS caps schedulable utilisation at ~69%; EDF can reach 100% on a uniprocessor.

Practice MCQs

Q1. SJF (Shortest Job First) is optimal for:

  1. response time
  2. minimising average waiting time
  3. fairness
  4. throughput of long jobs
Show answer

Answer: B. Provable by an exchange argument.

Q2. If the Round Robin quantum is too small:

  1. response time worsens
  2. context-switch overhead dominates
  3. it behaves like SJF
  4. starvation occurs
Show answer

Answer: B. Too large ⇒ RR degenerates into FCFS.

Q3. The convoy effect occurs in:

  1. Round Robin
  2. FCFS — short jobs wait behind one long job
  3. SJF
  4. multilevel feedback
Show answer

Answer: B. It reduces CPU and device utilisation.

Q4. Aging in scheduling means:

  1. killing old processes
  2. raising the priority of long-waiting processes to prevent starvation
  3. lowering priority over time
  4. clearing the ready queue
Show answer

Answer: B. It bounds any process's waiting time.

Q5. Multilevel FEEDBACK queue scheduling:

  1. never moves processes
  2. moves processes between queues by behaviour, approximating SJF without known burst times
  3. uses only FCFS
  4. requires known burst times
Show answer

Answer: B. CPU-heavy jobs sink; I/O-heavy jobs stay high.
