Deadlock

Deadlock is a set of processes each permanently blocked waiting for a resource another holds. It needs all four Coffman conditions at once; breaking any one prevents it. Approaches: prevention, avoidance (Banker's), detection & recovery, or ignore it.

Key points

Coffman conditions
Mutual exclusion, hold-and-wait, no preemption, circular wait — all four must hold.
Prevention
Structurally deny one condition: request all resources up front (no hold-and-wait), make resources preemptible, or impose a global resource ordering (no circular wait).
Avoidance (Banker's)
Needs each process's maximum claim. Grant a request only if the resulting state is 'safe' (a completion order exists). Conservative — may deny safe-looking requests.
Detection & recovery
Wait-for graph (single-instance: a cycle = deadlock); recover by aborting a victim or rolling it back to a checkpoint.
Deadlock vs starvation vs livelock
Deadlock: permanently stuck, system stalls. Starvation: one process indefinitely delayed, system progresses. Livelock: busy but no progress.

Example

Banker's algorithm — safety check:
  Work = Available;  Finish[i] = false for all i
  repeat:
    find i with Finish[i] == false AND Need[i] <= Work
    if found: Work += Allocation[i];  Finish[i] = true
    else break
  if all Finish[i] == true  →  SAFE state

Grant a request only if Request <= Need, Request <= Available,
and the resulting state passes this check; otherwise the process waits.
Common exam traps

'Bounded waiting' is a critical-section property, NOT a Coffman condition (the fourth is 'no preemption'). An unsafe state is not necessarily deadlocked — the OS just lost the guarantee. A cycle means deadlock only for single-instance resources. Most general-purpose OSes use the ostrich algorithm for user processes.

Practice MCQs

Q1. The four Coffman conditions are:

  1. preemption, sharing, ordering, waiting
  2. mutual exclusion, hold-and-wait, no preemption, circular wait
  3. starvation, aging, priority, quantum
  4. fetch, decode, execute, stall
Show answer

Answer: B. All four must hold simultaneously.

Q2. Deadlock AVOIDANCE (Banker's algorithm) requires:

  1. no information
  2. advance knowledge of each process's maximum resource needs
  3. a resource-allocation graph only
  4. killing processes
Show answer

Answer: B. It grants a request only if the resulting state is safe.

Q3. A 'safe state' means:

  1. no process is running
  2. an ordering exists in which every process can obtain its max resources, run and release
  3. the system is idle
  4. no resources are allocated
Show answer

Answer: B. A safe state is deadlock-free.

Q4. Requiring a process to request ALL resources before starting prevents:

  1. circular wait
  2. hold and wait
  3. mutual exclusion
  4. no preemption
Show answer

Answer: B. Downside: low utilization and possible starvation.

Q5. A livelock is:

  1. a deadlock that resolves
  2. processes not blocked but continually reacting to each other without progressing
  3. a lock that never releases
  4. normal operation
Show answer

Answer: B. CPU is busy; randomized backoff usually breaks it.
