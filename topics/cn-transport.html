TCP/UDP, Sockets & Congestion Control

TCP and UDP deliver data between processes (via ports) on top of IP. TCP adds reliability, ordering, flow control and congestion control; UDP stays minimal and fast. Congestion control keeps many competing flows from collapsing the shared network.

Key points

TCP vs UDP
TCP: connection-oriented, reliable, ordered byte stream (3-way handshake). UDP: connectionless, best-effort, minimal 8-byte header, preserves datagram boundaries.
Sockets
An endpoint identified by (IP, port). Server flow: socket → bind → listen → accept. Client flow: socket → connect.
Flow control
TCP's receive window (rwnd) tells the sender how much buffer space the receiver currently has.
Congestion control
Slow start (exponential growth) → congestion avoidance (linear growth, AIMD) → multiplicative decrease on loss. The sender's actual window = min(cwnd, rwnd).
Fast retransmit / recovery
Three duplicate ACKs trigger an immediate retransmission (no timeout wait) and a milder window cut than a full timeout would cause.

Example

Three-way handshake:

Client              Server
  | ---- SYN (seq=x) --------> |
  | <--- SYN-ACK (seq=y,       |
  |       ack=x+1) ----------- |
  | ---- ACK (ack=y+1) ------> |
  |                            |
  |  == connection established, data can now flow ==

TCP send window = min(cwnd, rwnd)
  cwnd = 10 MSS (network can currently handle this)
  rwnd = 4 MSS  (receiver's buffer is nearly full)
  -> sender may only send 4 MSS worth of unacked data
Common exam traps

Flow control protects the RECEIVER (rwnd); congestion control protects the NETWORK (cwnd) — do not conflate them. TCP preserves byte-stream order with no message boundaries; UDP preserves datagram boundaries. A timeout triggers a full return to slow start; three duplicate ACKs trigger the gentler fast retransmit/fast recovery. DNS commonly uses UDP; HTTP/FTP/SMTP use TCP.

Practice MCQs

Q1. TCP provides which type of service?

  1. Connectionless, unreliable delivery
  2. Connection-oriented, reliable, ordered byte-stream delivery
  3. Broadcast-only delivery
  4. Circuit-switched delivery
Show answer

Answer: B. Achieved via sequence numbers, ACKs, checksums and retransmission.

Q2. TCP's connection establishment is known as:

  1. The two-way handshake
  2. The three-way handshake (SYN, SYN-ACK, ACK)
  3. The four-way handshake
  4. The zero-way handshake
Show answer

Answer: B. Synchronizes initial sequence numbers on both sides.

Q3. TCP's slow start works by:

  1. Starting at the maximum window immediately
  2. Starting small and roughly doubling the congestion window each RTT until a threshold or loss
  3. Sending at a fixed constant rate forever
  4. Refusing to send any data initially
Show answer

Answer: B. Quickly (but cautiously) probes for available bandwidth.

Q4. AIMD describes TCP congestion control as:

  1. Increasing exponentially forever with no decrease
  2. Increasing the window gradually, but cutting it sharply on detected congestion
  3. Keeping the window constant always
  4. Changing the window randomly
Show answer

Answer: B. Additive Increase, Multiplicative Decrease — the classic "sawtooth".

Q5. A socket is best described as:

  1. A physical cable connector
  2. An endpoint for network communication, identified by IP address and port
  3. A type of router
  4. A DNS record
Show answer

Answer: B. The socket API lets applications send/receive over TCP or UDP.
