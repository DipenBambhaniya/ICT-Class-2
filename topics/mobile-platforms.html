Mobile Platforms & Devices

From early PDAs to today's smartphones, mobile platforms combine hardware (SoC, sensors, touchscreens) with a layered OS (Android/iOS) that runs sandboxed apps. Understanding this architecture explains why mobile software is built and constrained the way it is.

Key points

PDA → smartphone
A PDA (Personal Digital Assistant) was a standalone organizer with no cellular voice/data; merging that with a phone produced the smartphone.
Android vs iOS
Android: Linux kernel + HAL + ART runtime + app framework, relatively open (sideloading allowed). iOS: Core OS → Core Services → Media → Cocoa Touch, closed ecosystem (App Store only).
App sandboxing
Each app is isolated in its own storage/resources, limiting what a compromised or malicious app can access.
Runtime permissions
Sensitive permissions (camera, location) are requested at the point of use, not bundled at install time.
SoC & sensors
A System on Chip integrates CPU/GPU/modem; accelerometer, gyroscope, GPS and capacitive touchscreens are the standard sensor suite.

Example

A camera app on Android requests the CAMERA permission:
  1. App calls the Camera API (Application Framework layer)
  2. OS checks: has the user granted CAMERA at runtime? If not, shows a
     permission dialog right when the feature is first used (not at install)
  3. If granted, the framework talks to the Camera HAL
  4. HAL talks to the actual camera driver in the Linux kernel
  5. Kernel controls the physical camera hardware, sandboxed so only
     this app's granted access applies
Common exam traps

Android is Linux-kernel-based and relatively open (sideloading allowed); iOS is closed (App Store only) and unrelated to Linux. Runtime permissions ≠ install-time permissions — modern Android/iOS ask at point of use. A PDA historically had no built-in cellular voice/data; that's exactly what merging with a phone added to create the smartphone.

Practice MCQs

Q1. Android's operating system is built on top of which kernel?

  1. Windows NT kernel
  2. The Linux kernel
  3. The Darwin (BSD) kernel
  4. No kernel — Android runs bare-metal
Show answer

Answer: B. Android uses a modified Linux kernel for core OS services like process and memory management.

Q2. App sandboxing on mobile OSes means:

  1. All apps freely share the same storage and data by default
  2. Each app is restricted to its own isolated storage/resources, unable to directly access another app's data without explicit permission
  3. Apps cannot access any device storage at all
  4. Sandboxing only applies to system apps
Show answer

Answer: B. Sandboxing limits the damage a compromised or malicious app can do to the rest of the system.

Q3. Runtime permissions (e.g., in Android 6.0+) mean that:

  1. All permissions are granted automatically at install with no user involvement
  2. Apps must request sensitive permissions (camera, location, etc.) at the point of use, and the user can grant or deny each one
  3. Permissions can never be revoked once granted
  4. Only system apps require any permissions
Show answer

Answer: B. This contrasts with older models that granted all requested permissions in a single bundle at install time.

Q4. A PDA (Personal Digital Assistant) was best described as:

  1. A modern 5G smartphone
  2. An early handheld device for personal information management (calendar, contacts, notes) that predated modern smartphones
  3. A type of cellular base station
  4. A desktop operating system
Show answer

Answer: B. PDAs later merged with cellular phones to form what we now call smartphones.

Q5. A SoC (System on Chip) in a mobile device integrates:

  1. Only the display panel
  2. CPU, GPU, memory controller, and often the modem, onto a single chip for space and power efficiency
  3. Only the battery
  4. Only the camera sensor
Show answer

Answer: B. Integrating these components onto one chip reduces size and power consumption compared to discrete components.
