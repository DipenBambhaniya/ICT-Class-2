Processes

A process is a program in execution with its own address space, tracked by the OS via a Process Control Block. It moves through New → Ready → Running → Waiting → Terminated as it competes for the CPU and waits on I/O.

Key points

PCB
The OS's per-process record: state, PC, registers, memory limits, open files, PID, scheduling info. Saved/restored on a context switch (pure overhead).
Five states
New (being created), Ready (waiting for CPU), Running, Waiting/Blocked (on I/O or an event), Terminated.
fork / exec / wait / exit
fork() clones the process (COW); exec() replaces its image; wait() reaps a child (else it is a zombie); exit() terminates it.
Schedulers
Long-term (admission / degree of multiprogramming), medium-term (swapping), short-term (which ready process runs next — runs on every ms).
Zombie vs orphan
Zombie: dead child not yet wait()ed. Orphan: parent died first; adopted by init (PID 1).

Diagram

Example

pid_t pid = fork();
if (pid == 0) {                 // child: pid == 0
    execlp("ls", "ls", "-l", NULL);   // replace image; never returns on success
    _exit(127);                 // exec failed
} else {                        // parent: pid == child's PID
    int status;
    waitpid(pid, &status, 0);   // reap the child (avoid a zombie)
}
Common exam traps

A program is passive (a file); a process is active. fork() returns twice: 0 to the child, the child's PID to the parent. A context switch does no useful work. A zombie holds only a PCB (until wait()); an orphan is a live process adopted by init.

Practice MCQs

Q1. The Process Control Block (PCB) stores:

  1. only the process name
  2. state, PC, registers, memory limits, open files, PID, scheduling info
  3. the source code
  4. only the priority
Show answer

Answer: B. It is saved/restored on every context switch.

Q2. A process moves from Running to Waiting when:

  1. its quantum expires
  2. it requests I/O or waits on an event
  3. it is dispatched
  4. it is admitted
Show answer

Answer: B. Running→Ready is preemption; Running→Waiting is I/O.

Q3. fork() returns:

  1. 0 in both processes
  2. 0 to the child, the child's PID to the parent
  3. the parent's PID to the child
  4. -1 always
Show answer

Answer: B. This is how each process knows its role.

Q4. A zombie process is:

  1. one using 100% CPU
  2. a terminated child whose exit status has not been wait()ed
  3. stuck in a loop
  4. malicious
Show answer

Answer: B. The PCB lingers until the parent reaps it.

Q5. The short-term scheduler:

  1. admits new jobs
  2. selects which ready process runs next; runs very frequently
  3. swaps processes to disk
  4. handles page faults
Show answer

Answer: B. It must be fast because it runs on every scheduling decision.
