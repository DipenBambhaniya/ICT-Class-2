Normal Forms

Normalization is the process of decomposing relations to remove redundancy and update, insert and delete anomalies. Each normal form is a stricter test based on the functional dependencies that hold on the relation.

Building blocks

Functional dependency (FD) X → Y
The value of attribute set X uniquely determines the value of attribute set Y. E.g. Roll_No → Name.
Prime vs non-prime attribute
A prime attribute belongs to some candidate key; a non-prime attribute belongs to none.
Partial dependency
A non-prime attribute depends on part of a composite candidate key (attacked by 2NF).
Transitive dependency
A non-prime attribute depends on another non-prime attribute (attacked by 3NF).

Diagram — the normalization ladder

The forms at a glance

FormRequirement (given all lower forms hold)Removes
1NFAll attributes hold atomic (indivisible) values; no repeating groups or multivalued cellsNon-atomic data
2NFNo non-prime attribute is partially dependent on any candidate key (full functional dependency)Partial dependency
3NFNo non-prime attribute is transitively dependent on a candidate key. For every FD X→A, X is a superkey OR A is primeTransitive dependency
BCNFFor every non-trivial FD X→Y, X must be a superkey (stricter than 3NF)Anomalies from overlapping candidate keys
4NFNo non-trivial multivalued dependency unless the determinant is a superkeyMultivalued dependency
5NF (PJ/NF)Every join dependency is implied by the candidate keysJoin dependency

Example — 1NF to 3NF

Unnormalized:
STUDENT(Roll, Name, Courses[])          -- "Courses" holds {DBMS, OS}

1NF  (make values atomic):
STUDENT_COURSE(Roll, Name, Course)      -- one row per (Roll, Course)
    Candidate key = {Roll, Course}

2NF  (remove partial dependency Roll -> Name):
STUDENT(Roll, Name)
ENROLL(Roll, Course)

Now add: STUDENT(Roll, Name, Dept, HOD)  with  Dept -> HOD
3NF  (remove transitive dependency Roll -> Dept -> HOD):
STUDENT(Roll, Name, Dept)
DEPARTMENT(Dept, HOD)
Common exam traps

2NF only matters when the key is composite — a single-attribute key can have no partial dependency, so it is automatically 2NF. Every BCNF relation is in 3NF, but not vice-versa. 3NF decomposition is always lossless and dependency-preserving; BCNF decomposition is lossless but may not preserve all dependencies.

Practice MCQs

Q1. A relation is in 2NF if it is in 1NF and:

  1. Every determinant is a candidate key
  2. No non-prime attribute has a partial dependency on a candidate key
  3. There are no transitive dependencies
  4. It has no multivalued dependencies
Show answer

Answer: B. 2NF eliminates partial dependencies — a non-prime attribute must depend on the whole candidate key, not just part of a composite key. Option A describes BCNF; option C describes 3NF.

Q2. In R(A, B, C) with candidate key A and FDs A→B and B→C, R is in:

  1. 1NF only (transitive dependency A→B→C)
  2. 2NF but not 3NF
  3. 3NF and BCNF
  4. Not even 1NF
Show answer

Answer: B. Key A is single-attribute so there is no partial dependency → 2NF holds. But C is a non-prime attribute transitively dependent on A through B (A→B→C), which violates 3NF.

Q3. Which normal form deals with removing repeating groups / non-atomic attribute values?

  1. 1NF
  2. 2NF
  3. 3NF
  4. BCNF
Show answer

Answer: A — 1NF. First normal form requires that every attribute contains only atomic (single, indivisible) values, with no arrays, sets or repeating groups.

Q4. A relation is in BCNF if, for every non-trivial functional dependency X → Y:

  1. Y is a prime attribute
  2. X is a superkey
  3. X is a single attribute
  4. Y is fully dependent on X
Show answer

Answer: B. BCNF requires the left side (determinant) of every non-trivial FD to be a superkey. This is stricter than 3NF, which also allows the case where Y is a prime attribute.

Q5. Which anomaly is NOT typically caused by redundancy in an un-normalized relation?

  1. Insertion anomaly
  2. Deletion anomaly
  3. Update anomaly
  4. Deadlock
Show answer

Answer: D — Deadlock. Deadlock is a concurrency-control problem. Insertion, deletion and update anomalies are exactly the redundancy problems that normalization removes.

Q6. 4NF is concerned with eliminating:

  1. Transitive dependencies
  2. Partial dependencies
  3. Non-trivial multivalued dependencies
  4. Join dependencies
Show answer

Answer: C. 4NF removes non-trivial multivalued dependencies (where a determinant is not a superkey). Join dependencies are the concern of 5NF.
