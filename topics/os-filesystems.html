File Systems

A file system turns a raw block device into a namespace of named files: it allocates blocks, stores metadata in inodes, manages free space, enforces access control, and maintains crash consistency (journaling or copy-on-write).

Key points

Inode
Metadata (size, permissions, timestamps, owner) + data-block pointers. The NAME lives in the directory entry (name → inode number).
Allocation
Contiguous (fast, external fragmentation), linked (no fragmentation, poor random access), indexed (Unix inode: direct + single/double/triple indirect, or extents).
Hard vs symbolic link
Hard link: another directory entry for the same inode (data persists until link count 0; cannot cross file systems). Symlink: a path string; can dangle; can cross file systems.
Free-space & consistency
Bitmap or free-list. Journaling writes metadata to a log first (recover by replay); copy-on-write (ZFS/Btrfs) writes new blocks and swaps the root (cheap snapshots).
Caching & durability
The page cache buffers reads/writes; writes are flushed lazily. fsync() forces a file's data to durable storage.

Diagram

Example

Atomic file update (safe against crashes):
  1. write new content to  report.txt.tmp
  2. fsync(tmp_fd)                 // force data to disk
  3. rename("report.txt.tmp", "report.txt")   // atomic replace

Deleting a file = unlink() — removes ONE name. Blocks are freed only when
the link count is 0 AND no process still has the file open.
Common exam traps

The file NAME is in the directory entry, not the inode. Hard links cannot cross file systems (inode numbers are per-FS) but symlinks can. A file unlinked while open stays readable until the last fd closes (this causes df/du discrepancies). On SSDs, disk-head scheduling barely matters — TRIM and write amplification do. Journaling protects consistency, not read speed.

Practice MCQs

Q1. An inode stores:

  1. the file's name
  2. metadata and data-block pointers — but NOT the name
  3. only the data
  4. the directory tree
Show answer

Answer: B. The name is in the directory entry (name → inode number).

Q2. A symbolic (soft) link is:

  1. another name for the same inode
  2. a file containing a path to the target; can dangle and can cross file systems
  3. a hard link to a directory
  4. a backup
Show answer

Answer: B. Resolving it is an extra lookup.

Q3. Indexed allocation (Unix inode):

  1. stores a next-block pointer in each block
  2. keeps block pointers in an index block (direct + indirect) — fast random access, no external fragmentation
  3. requires contiguous space
  4. stores data in the directory
Show answer

Answer: B. Direct + single/double/triple indirect blocks scale to huge files.

Q4. Journaling file systems improve:

  1. read speed
  2. crash consistency — changes are logged before being applied
  3. compression
  4. encryption
Show answer

Answer: B. It avoids a slow full fsck after an unclean shutdown.

Q5. A file opened by one process and unlink()ed by another:

  1. causes an error
  2. stays accessible to the first process until it closes the fd
  3. is immediately gone
  4. cannot happen
Show answer

Answer: B. Space is reclaimed after the last close.
