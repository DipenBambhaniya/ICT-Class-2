Network Security

Security combines authentication (verifying identity), cryptography (confidentiality, integrity, trust) and network controls (firewalls, segmentation) as layered, complementary defenses — no single mechanism is sufficient alone.

Key points

Authentication vs authorization
Authentication verifies WHO you are (password, token, biometric — ideally multiple factors). Authorization decides WHAT an authenticated identity may do.
Symmetric vs public-key crypto
Symmetric (AES): one shared secret key, fast, but key distribution is hard. Public-key (RSA/ECC): a key pair (public/private); solves distribution but is computationally heavier.
Digital signatures
Hash the message, then encrypt the hash with the SENDER's private key. Anyone can verify with the sender's public key — proves integrity AND authorship (non-repudiation).
Certificates & PKI
A certificate binds a public key to an identity, signed by a trusted Certificate Authority (CA). Browsers trust a chain from the certificate up to a trusted root CA.
Firewalls
Packet-filtering (headers only) → stateful (tracks connections) → application-layer (inspects content). Default-deny is the safer baseline policy.

Diagram

Example

TLS handshake (simplified) combining both crypto types:

1. Server presents its certificate (contains its PUBLIC key,
   signed by a trusted CA)
2. Client verifies the certificate chain up to a trusted root CA
3. Client and server use asymmetric crypto to securely agree
   on a SHARED SYMMETRIC session key
4. All further data is encrypted with fast symmetric crypto
   (e.g. AES) using that session key

-> asymmetric crypto solves key exchange; symmetric crypto
   handles the actual bulk data efficiently.
Common exam traps

A digital signature is made with the SENDER's private key and verified with the sender's public key — the reverse of confidential encryption (encrypt with the RECIPIENT's public key). Hashing is one-way (for integrity/passwords); encryption is reversible (for confidentiality). MAC filtering and SSID hiding are NOT strong security. A firewall alone does not stop an already-authorized insider or malicious content riding over an allowed port — defense in depth uses multiple layered controls.

Practice MCQs

Q1. Authentication refers to:

  1. Encrypting data
  2. Verifying the claimed identity of a user or system
  3. Ensuring data isn't modified in transit
  4. Making a resource available
Show answer

Answer: B. Distinct from authorization (what you're allowed to do).

Q2. Symmetric-key cryptography uses:

  1. A public and a private key
  2. The same secret key for encryption and decryption
  3. No key at all
  4. A key that changes every bit
Show answer

Answer: B. Both parties must securely share this same key beforehand.

Q3. A digital signature is created by:

  1. Encrypting the message with the recipient's public key
  2. Hashing the message, then encrypting that hash with the sender's private key
  3. Attaching the sender's name as plain text
  4. Using only symmetric encryption
Show answer

Answer: B. Anyone can verify it with the sender's public key.

Q4. A Certificate Authority (CA) is responsible for:

  1. Generating a website's private key for itself
  2. Verifying identity and signing a certificate binding it to a public key
  3. Encrypting all HTTPS traffic directly
  4. Storing every user's password
Show answer

Answer: B. Browsers trust a chain up to a root CA.

Q5. A stateful firewall improves on packet filtering by:

  1. Ignoring all connection context
  2. Tracking active connection state to make smarter filtering decisions
  3. Encrypting every packet automatically
  4. Only working with UDP
Show answer

Answer: B. It can recognize legitimate return traffic for an already-established connection.
