Agile Software Development

Agile replaces one big upfront plan with short, feedback-driven cycles. Scrum structures this with fixed Sprints, defined roles and ceremonies; Kanban emphasizes continuous flow with WIP limits; Extreme Programming (XP) adds engineering practices like TDD and pair programming.

Key points

Agile Manifesto
Individuals/interactions over processes/tools, working software over documentation, customer collaboration over contract negotiation, responding to change over following a plan.
Scrum roles
Product Owner (prioritizes the "what"), Scrum Master (facilitates process, removes blockers), Development Team (self-organizes the "how").
Scrum events
Sprint Planning → Daily Scrum (each day) → Sprint Review (demo to stakeholders) → Sprint Retrospective (team process improvement).
Kanban
Visual board + WIP limits, continuous flow — no fixed-length Sprints, contrasting with Scrum's time-boxed structure.
XP practices
Pair programming, Test-Driven Development (red-green-refactor), Continuous Integration, refactoring, frequent small releases.

Diagram

Example

A 2-week Sprint for a food-delivery app team:
  Day 1    Sprint Planning: Product Owner presents top backlog items;
           team commits to 8 user stories (34 story points) into the
           Sprint Backlog
  Days 2-9 Daily Scrum each morning (15 min): "yesterday / today / blockers"
           Developers pair-program the payment-retry story using TDD:
           write a failing test for "retry on network timeout" -> make
           it pass -> refactor
  Day 10   Sprint Review: demo the completed stories to stakeholders,
           who ask for one tweak to the retry UI (goes into next backlog)
           Sprint Retrospective: team notices code review is a bottleneck,
           agrees to review PRs within 4 hours going forward
Common exam traps

The Product Owner owns the backlog/priorities; the Scrum Master facilitates process and removes blockers — these roles are often swapped in questions. Scrum uses fixed-length Sprints; Kanban does not. Story points measure relative effort/complexity, NOT hours. TDD's cycle is write failing test → make it pass → refactor, in that order.

Practice MCQs

Q1. In Scrum, the Product Owner's primary responsibility is to:

  1. Write all the code personally
  2. Represent stakeholder/customer interests, prioritize the Product Backlog, and define what should be built
  3. Facilitate daily standups only
  4. Manage the team's HR issues
Show answer

Answer: B. The Product Owner owns the 'what' and 'why' of the product, prioritizing value for stakeholders.

Q2. The Sprint Retrospective, a Scrum event, is held to:

  1. Demonstrate the product to external stakeholders
  2. Reflect on the team's own process and identify improvements for how they work together going forward
  3. Plan the next release's marketing
  4. Only occur at the very end of the entire project
Show answer

Answer: B. The Retrospective is inward-facing, focused on continuous team process improvement, unlike the outward-facing Sprint Review.

Q3. Test-Driven Development (TDD), an XP practice, follows the cycle:

  1. Write code first, then decide whether to test it later
  2. Write a failing test first, then write just enough code to make it pass, then refactor
  3. Only write tests after the entire project is finished
  4. Skip testing entirely and rely on manual QA
Show answer

Answer: B. This 'red-green-refactor' cycle is the core discipline of TDD.

Q4. A key difference between Scrum and Kanban is that Scrum uses:

  1. Continuous flow with no defined roles, unlike Kanban
  2. Fixed-length Sprints with defined roles/ceremonies, while Kanban emphasizes continuous flow without mandatory time-boxed iterations
  3. Exactly the same structure as Kanban with no differences
  4. No backlog at all, unlike Kanban
Show answer

Answer: B. This structural distinction (time-boxed vs. continuous flow) is the key differentiator between the two methods.

Q5. Story points in Agile estimation represent:

  1. A direct measure of hours or days
  2. A relative measure of effort/complexity/uncertainty for completing a piece of work, rather than a direct measure of time
  3. A count of the number of bugs in a feature
  4. A financial cost estimate in currency
Show answer

Answer: B. Story points deliberately avoid direct time units, focusing on relative sizing instead.
