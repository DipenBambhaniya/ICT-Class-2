Sorting & Hashing

Comparison sorts are bounded by Ω(n log n); non-comparison sorts (counting, radix, bucket) beat it by using key values. Hashing gives O(1) average operations by mapping keys to buckets and resolving collisions.

Key points

Comparison-sort bound
Ω(n log n) — a decision tree with n! leaves has height ≥ log₂(n!).
Merge / Quick / Heap sort
n log n (merge always; quick average; heap always). Merge is stable, O(n) space; heap is in-place; quick has O(n²) worst case.
Non-comparison sorts
Counting O(n+k), radix O(d(n+b)), bucket O(n) expected for uniform data.
Collision resolution
Separate chaining (list per bucket) or open addressing (linear/quadratic/double probing).
Load factor α = n/m
Performance degrades as α → 1 (open addressing) or grows (chaining); resize (rehash) to keep operations O(1) amortized.

// Polynomial string hash (Rabin-Karp), rolling in O(1):
h = (h * p + s[i]) mod m           // add a char
h = (h - s[i-L] * p^(L-1)) * ... mod m   // remove the oldest char

// Load factor management: when n/m > 0.7, allocate 2m buckets and rehash

Common exam traps

Quicksort, heapsort and selection sort are NOT stable. Counting sort is O(n+k) — only good when k = O(n). Merge sort is preferred for linked lists and external sorting; quicksort wins in RAM (cache, constants). Modulo hashing (key % m) remaps almost every key when m changes — use consistent hashing for distributed caches.

Practice MCQs

Q1. The comparison-sort lower bound is:

  1. Omega(n)
  2. Omega(n log n)
  3. Omega(n^2)
  4. Omega(log n)
Show answer

Answer: B. log2(n!) = Omega(n log n).

Q2. Which sort is NOT comparison-based?

  1. merge sort
  2. quicksort
  3. counting sort
  4. heapsort
Show answer

Answer: C. It uses key values directly.

Q3. Which sorts are stable (typical implementations)?

  1. quicksort and heapsort
  2. merge sort, insertion sort, counting sort
  3. heapsort and selection sort
  4. only radix sort
Show answer

Answer: B. Quicksort/heapsort/selection are not stable.

Q4. Linear probing suffers from:

  1. secondary clustering
  2. primary clustering (long contiguous runs)
  3. no clustering
  4. underflow
Show answer

Answer: B. Adjacent collisions merge into runs.

Q5. When a hash table's load factor exceeds a threshold, it is:

  1. cleared
  2. resized (rehashed) to a larger table
  3. converted to a BST
  4. left as is
Show answer

Answer: B. Doubling keeps operations amortized O(1).
