Memory & Virtual Memory

Virtual memory gives each process a large private address space, using paging to map virtual pages to physical frames (via the page table and TLB) and demand paging to load pages from disk only when touched. Over-committing memory risks thrashing.

Key points

Paging
Virtual space → fixed-size pages; physical → equal frames. No external fragmentation; internal fragmentation ~ half a page per region.
Page table + TLB
The page table maps VPN → frame; the TLB caches recent translations. A TLB miss walks the (multi-level) table; a context switch flushes the TLB unless it is ASID-tagged.
Demand paging & page fault
Pages load on first reference. A fault ⇒ OS finds a free frame (or evicts a victim, writing it back if the dirty bit is set), loads the page, restarts the instruction.
Replacement algorithms
OPT (optimal, unrealisable), FIFO (can show Belady's anomaly), LRU (stack algorithm — no anomaly), Clock / second-chance (LRU approximation using a reference bit).
Thrashing & working set
If Σ working sets > RAM, processes page constantly and CPU utilisation collapses. Fix: reduce the degree of multiprogramming (swap a process out).

Example

4 KB pages, 32-bit virtual address:
   [ 20-bit page number | 12-bit offset ]   (2^12 = 4096)

Page-replacement on reference string  1 2 3 4 1 2 5 1 2 3 4 5  with 3 frames:
   FIFO  → 9 faults
   LRU   → 10 faults ... (LRU never shows Belady's anomaly; FIFO with 4 frames
           gives MORE faults than with 3 — that's the anomaly)

TLB effective access time (98% hit, 1 ns TLB, 100 ns mem):
   0.98·(1+100) + 0.02·(1+100+100) = 103 ns
Common exam traps

Belady's anomaly (more frames ⇒ more faults) affects FIFO but never stack algorithms (LRU, OPT). OPT is optimal but unrealisable. Paging has internal, not external, fragmentation; segmentation is the reverse. A clean (non-dirty) victim page needs no write-back. A context switch flushes an untagged TLB.

Practice MCQs

Q1. Internal fragmentation in paging comes from:

  1. gaps between allocations
  2. the last page of a region being only partly used
  3. the page table
  4. swapping
Show answer

Answer: B. Average waste ~ half a page per region.

Q2. A page fault occurs when:

  1. the page table is full
  2. a referenced page is not in physical memory
  3. the TLB is full
  4. two processes share a page
Show answer

Answer: B. The OS loads it and restarts the instruction.

Q3. FIFO page replacement can suffer from:

  1. optimal behaviour
  2. Belady's anomaly — more frames causing more faults
  3. no faults ever
  4. TLB thrashing only
Show answer

Answer: B. LRU and OPT are stack algorithms and never show it.

Q4. Thrashing is:

  1. fast paging
  2. spending more time paging than executing because working sets exceed RAM
  3. a disk failure
  4. TLB misses
Show answer

Answer: B. Fix: reduce the degree of multiprogramming.

Q5. The clock (second-chance) algorithm approximates LRU using:

  1. full timestamps
  2. a per-page reference bit, cleared on a sweep before eviction
  3. the page-table size
  4. random selection
Show answer

Answer: B. Cheap: one hardware bit per page.
