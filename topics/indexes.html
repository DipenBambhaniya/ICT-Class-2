Indexes

An index is a small auxiliary structure storing (search-key value → pointer) entries in sorted order, so the DBMS can locate rows without scanning the whole table. It speeds up reads at the cost of extra storage and slower writes.

Classification

Primary index
Built on the ordering key field of a sequentially organized file (one entry per block — sparse). At most one per table.
Clustering index
Built on an ordering non-key field (values repeat). One entry per distinct value. The data file is physically ordered by this field.
Secondary index
Built on a non-ordering field. Must be dense (one entry per record, or one per distinct value with buckets). Many allowed per table.
Dense vs sparse
Dense: an index entry for every search-key value in the data file. Sparse: an index entry only for some values (e.g. one per block) — smaller, but the data file must be ordered.
Multi-level index
An index on the index — repeated until the top level fits in one block. A B+ tree is the dynamic form of a multi-level index.

  • Composite index on (A, B): usable for predicates on A, or A+B, but not B alone (leftmost-prefix rule).
  • Covering index: contains every column the query needs, so the table itself is never read.
  • Cost: every INSERT/UPDATE/DELETE must also maintain each affected index, and indexes consume disk space.

Example — index blocking

Data:  r = 30000 records, B = 1500 blocks (bfr = 20)
Index entry = key(9 B) + pointer(6 B) = 15 B,  block = 4096 B
Index blocking factor  = floor(4096 / 15) = 273 entries/block

Sparse primary index (1 entry per data block):
   index entries = 1500  ->  index blocks = ceil(1500 / 273) = 6
   search cost = log2(6) + 1  ≈ 4 block reads   (vs 750 for a heap scan)

Dense secondary index (1 entry per record):
   index entries = 30000 ->  index blocks = ceil(30000 / 273) = 110
Common exam traps

A primary index is on the ordering key and is sparse; a secondary index is on a non-ordering field and must be dense. A table can have only one primary/clustering index (physical order) but many secondary indexes. An index does not change query results — only speed. Over-indexing hurts write-heavy workloads.

Practice MCQs

Q1. An index that has one entry for every distinct search-key value in the data file is called:

  1. Sparse index
  2. Dense index
  3. Primary index
  4. Secondary index
Show answer

Answer: B — Dense index. A sparse index stores entries for only some values (typically one per block) and therefore requires the data file to be ordered on that field.

Q2. A primary index is built on:

  1. A non-ordering, non-key field
  2. The ordering key field of a sequentially ordered file
  3. Any candidate key
  4. The most frequently queried column
Show answer

Answer: B. A primary index is defined on the field that both is the primary/ordering key and determines the physical sort order of the file, so it can be sparse (one entry per block).

Q3. Which type of index MUST be dense?

  1. Primary index
  2. Clustering index
  3. Secondary index on a non-ordering field
  4. Sparse multi-level index
Show answer

Answer: C. Because the data file is not ordered on a secondary field, the index cannot rely on block anchors — it needs an entry for every record (or every distinct value plus buckets).

Q4. A composite index on (Last_Name, First_Name) can be used efficiently for a query filtering only on:

  1. First_Name
  2. Last_Name
  3. First_Name OR Last_Name equally
  4. Neither column
Show answer

Answer: B — Last_Name. By the leftmost-prefix rule an ordered composite index supports predicates on a leading prefix of its columns, so Last_Name alone works but First_Name alone does not.

Q5. Which is a genuine disadvantage of adding many indexes to a table?

  1. SELECT queries return wrong rows
  2. INSERT, UPDATE and DELETE become slower and use more storage
  3. The table can no longer have a primary key
  4. Range queries stop working
Show answer

Answer: B. Every write must update all affected indexes, and each index occupies disk space; correctness of results is unaffected.

Q6. A "multi-level index" is essentially:

  1. An index stored on multiple disks
  2. An index built on top of another (lower-level) index
  3. An index with multiple search keys
  4. A hash index with several buckets
Show answer

Answer: B. When the first-level index is itself too large to search quickly, a second-level (sparse) index is built over it, repeating until the top level fits in one block — the idea B+ trees generalise.
