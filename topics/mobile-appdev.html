Mobile App Development

Building a mobile app means choosing between native, hybrid and cross-platform approaches, structuring code with patterns like MVC/MVVM, talking to a backend over REST/JSON, and shipping through a disciplined test-and-release pipeline.

Watch

▶ Watch: "Mobile App Development | Native vs Hybrid vs CrossPlatform Explained" (YouTube)

Key points

Native vs Hybrid vs Cross-platform
Native (Kotlin/Swift, best performance/API access) vs Hybrid (web UI in a WebView) vs Cross-platform (React Native/Flutter — one codebase, near-native rendering).
MVC / MVVM
MVC splits Model/View/Controller; MVVM adds an observable ViewModel between Model and View, suiting reactive/data-binding UI frameworks.
Backend communication
Apps typically talk to a server via REST APIs over HTTPS, exchanging JSON; local caching and SQLite support offline-first behavior.
CI/CD & testing
Unit tests (isolated logic), UI/instrumentation tests (simulated interaction), and automated pipelines that build/test/distribute on every change.
Distribution
Apple's App Store enforces review before publishing; Android additionally allows sideloading APKs outside the Play Store.

Example

A shopping app's checkout screen, built with MVVM:

  Model      -> Cart, Product, Order data classes + a repository that
                fetches/saves them via a REST API (GET /cart, POST /order)
  ViewModel  -> Exposes observable "cartTotal", "isLoading", "errorMessage"
                state; calls the repository, never touches UI widgets directly
  View       -> Binds to the ViewModel's observable state; when cartTotal
                changes, the UI updates automatically with no manual refresh

CI/CD pipeline on every commit: run unit tests (ViewModel logic) ->
run UI tests (tap "Checkout", assert order confirmation appears) ->
build a release APK/IPA -> publish to a beta testing track.
Common exam traps

"Hybrid" wraps a WebView; "cross-platform" (React Native/Flutter) renders closer to native widgets — these are often conflated. Runtime permissions belong to the Platforms topic, but requesting them at point-of-use (not all at install) is also a development best practice. Offline-first means the app stays usable without a network, not that it never syncs.

Practice MCQs

Q1. A native mobile app is built using:

  1. Only generic web technologies with no platform SDK
  2. The platform's own SDK and programming language (e.g., Kotlin/Java for Android, Swift/Objective-C for iOS), giving full access to platform APIs and best performance
  3. A single codebase that cannot access any device hardware
  4. Only server-side code with no client component
Show answer

Answer: B. Native development typically offers the best performance and deepest platform integration, at the cost of maintaining separate codebases per platform.

Q2. A cross-platform framework like React Native or Flutter allows developers to:

  1. Write completely separate code for each platform with no sharing
  2. Write app code largely once and deploy to multiple platforms, while still rendering natively (or near-natively) on each
  3. Only build web pages, never installable apps
  4. Avoid using any programming language
Show answer

Answer: B. These frameworks aim to combine much of native performance/feel with the development efficiency of a shared codebase.

Q3. A mobile app typically communicates with a remote backend server via:

  1. Only direct database file access
  2. REST (or similar) APIs over HTTP(S), exchanging data usually in JSON format
  3. Bluetooth exclusively
  4. Physical USB connection only
Show answer

Answer: B. REST-over-HTTP(S) with JSON is the most common pattern for mobile app-to-backend communication.

Q4. The MVVM (Model-View-ViewModel) pattern adds a:

  1. Database layer with no UI connection
  2. ViewModel layer that exposes data/state to the View in an observable way, helping separate UI logic from business logic
  3. Layer that eliminates the need for any Model
  4. Networking layer only
Show answer

Answer: B. MVVM is particularly well suited to frameworks with reactive/data-binding UI systems.

Q5. Continuous Integration/Continuous Deployment (CI/CD), applied to mobile app development, helps:

  1. Manually build and test each release by hand every time
  2. Automate building, testing, and (optionally) distributing new app versions on every code change
  3. Eliminate the need for any version control
  4. Guarantee the app never has any bugs
Show answer

Answer: B. CI/CD reduces manual effort and catches integration issues earlier through automated pipelines.
