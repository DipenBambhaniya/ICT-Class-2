Data Storage, Availability & Management

A data centre must store data reliably (durability), keep it reachable when needed (availability), and govern it properly through its life (management). Different storage architectures, replication strategies and backup schemes each trade off cost, performance and protection differently.

Key points

DAS / NAS / SAN
Direct-Attached (one host only), Network-Attached (shared file storage over a LAN), Storage Area Network (shared block storage over a dedicated high-speed fabric).
Block · File · Object
Block storage exposes raw addressable chunks (fast, used by databases); file storage exposes a folder hierarchy; object storage exposes flat, metadata-rich objects via an API (scales to billions of items).
RPO vs RTO
RPO (Recovery Point Objective) = how much data you can afford to lose, in time. RTO (Recovery Time Objective) = how long you can afford to be down.
Full · Incremental · Differential backup
Full copies everything; incremental copies changes since the last backup of any kind (fast, chained restore); differential copies changes since the last full (single-step restore, grows over time).
Hot / warm / cold tiers
Frequently used data stays on fast, expensive storage; rarely used data moves to slow, cheap storage — an application of information lifecycle management (ILM).

Example

A service takes a full backup every Sunday and an incremental backup every night.
It replicates asynchronously to a DR site every 15 minutes (RPO target = 15 min)
and has a hot standby site that can take over in under 5 minutes (RTO target = 5 min).

If the primary site fails at 10:07, having last replicated at 10:00:
  - Data loss window (RPO actually incurred) = 7 minutes of writes
  - Failover completes by 10:12                = 5 minutes of downtime (meets RTO)

Restoring instead from Sunday's full + nightly incrementals (no live replica) would
have a far larger RPO (up to a full day) and a far larger RTO (hours to restore + replay).
Common exam traps

RPO is about data LOSS (measured in time since last protected copy); RTO is about DOWNTIME (time to restore service) — they are frequently swapped in questions. Synchronous replication gives RPO≈0 but adds write latency; asynchronous replication is faster but risks losing the last few writes. A "successful" backup that was never restore-tested is not proven to be recoverable.

Practice MCQs

Q1. RPO (Recovery Point Objective) measures:

  1. How long a system can be down
  2. How much data (in time) can be lost since the last backup/replica
  3. The number of servers needed for recovery
  4. The encryption strength of a backup
Show answer

Answer: B. RTO is the downtime measure; RPO is the data-loss measure.

Q2. Which storage type exposes data as a flat namespace of items with metadata, accessed via a simple API?

  1. Block storage
  2. File storage
  3. Object storage
  4. DAS only
Show answer

Answer: C. Object storage (e.g., S3) scales to huge volumes of unstructured data without a hierarchical directory bottleneck.

Q3. An incremental backup, compared to a differential backup:

  1. Always copies everything, like a full backup
  2. Copies changes since the last backup of ANY kind, making restore require every increment in sequence
  3. Is identical to a differential backup
  4. Never needs a full backup at all
Show answer

Answer: B. A differential instead always copies changes since the last FULL backup, so restore needs only the full plus the latest differential.

Q4. Synchronous replication, compared to asynchronous replication:

  1. Has higher risk of data loss
  2. Confirms the write only after both sites have it, giving RPO≈0 at the cost of latency
  3. Cannot be used for disaster recovery
  4. Requires no network connection
Show answer

Answer: B. Asynchronous replication trades a small RPO risk for lower write latency, useful over long distances.

Q5. A "hot site" for disaster recovery is:

  1. The cheapest, slowest option to activate
  2. A fully operational duplicate facility with very low RTO, at high ongoing cost
  3. Only used for testing, never real failover
  4. The same thing as a cold site
Show answer

Answer: B. Cold sites are the cheap, slow-to-activate end of the spectrum; warm sites sit in between.
