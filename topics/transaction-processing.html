Transaction Processing

A transaction is a single logical unit of work — a sequence of read and write operations that must execute as an all-or-nothing whole, taking the database from one consistent state to another.

ACID properties

⚛️

Atomicity

All operations complete, or none do. A partial transaction is rolled back. Ensured by the recovery manager.

✅

Consistency

A transaction moves the DB from one valid state to another, preserving all integrity constraints.

🔒

Isolation

Concurrent transactions do not see each other's uncommitted intermediate state; the result equals some serial order. Ensured by the concurrency-control manager.

💾

Durability

Once committed, changes survive crashes — persisted via the write-ahead log.

Diagram — transaction state transitions

Example — a fund transfer

T:  transfer 500 from A to B
    BEGIN
    read(A)                A = 2000
    A := A - 500
    write(A)               -- crash here => atomicity must UNDO write(A)
    read(B)                B = 800
    B := B + 500
    write(B)
    COMMIT                 -- durability: once logged, survives a crash

Consistency rule preserved:  A + B is unchanged (2800 before and after).

Problems that appear without isolation

ProblemWhat happens
Lost updateTwo transactions read the same item and both write back; the first write is overwritten and lost
Dirty read (uncommitted dependency)T2 reads a value T1 wrote, then T1 aborts — T2 has used data that never officially existed
Unrepeatable readT1 reads an item twice and gets different values because T2 updated it in between
Phantom readT1 re-runs a range query and new rows inserted by T2 appear
Common exam traps

Atomicity and Durability are the recovery manager's job (log-based); Isolation is the concurrency-control manager's job (locks / timestamps). "Consistency" in ACID means integrity constraints hold — not the CAP meaning of replicas agreeing. A committed transaction can never be rolled back.

Practice MCQs

Q1. The property guaranteeing that a transaction executes completely or not at all is:

  1. Consistency
  2. Atomicity
  3. Isolation
  4. Durability
Show answer

Answer: B — Atomicity. If a transaction fails midway, the recovery manager undoes every change it made so the database shows an all-or-nothing effect.

Q2. A transaction that has executed its final operation but whose changes are not yet permanently written is in which state?

  1. Active
  2. Partially committed
  3. Committed
  4. Aborted
Show answer

Answer: B — Partially committed. It has finished computing but the system must still flush the log/buffers; only after that does it move to the committed state.

Q3. Transaction T2 reads a data item written by T1; T1 then aborts. This anomaly is a:

  1. Lost update
  2. Dirty read
  3. Phantom read
  4. Unrepeatable read
Show answer

Answer: B — Dirty read. T2 depended on an uncommitted value that was subsequently rolled back, so T2's computation is based on data that never committed.

Q4. Durability in a DBMS is typically implemented using:

  1. Two-phase locking
  2. A write-ahead / transaction log persisted to non-volatile storage
  3. Timestamp ordering
  4. Normalization
Show answer

Answer: B. Log records for a committed transaction are forced to disk before commit returns, so the changes can be redone after a crash even if the data pages were still in memory.

Q5. Which ACID property is enforced by the concurrency-control component?

  1. Atomicity
  2. Durability
  3. Isolation
  4. Consistency
Show answer

Answer: C — Isolation. Locking, timestamp ordering or MVCC make concurrent transactions behave as if they ran one after another. Atomicity and durability are handled by recovery.

Q6. Two transactions each read balance = 1000, each add 100, each write 1100. Final balance is 1100 instead of 1200. This is the:

  1. Phantom problem
  2. Lost update problem
  3. Deadlock problem
  4. Cascading rollback problem
Show answer

Answer: B — Lost update. The second write overwrites the first transaction's update, so one increment silently disappears. Locking or serialisable isolation prevents it.
