Inter-process Communication

Processes have separate address spaces, so the OS must mediate any data they exchange. The two models are shared memory (fast, you synchronize it yourself, single machine) and message passing (safer, kernel-mediated, works across machines).

Key points

Shared memory
Processes map a common region; after setup, reads/writes need no kernel call. You must add locks/semaphores. Lowest latency for bulk data on one host.
Message passing
send() / receive() via pipes, message queues, or sockets. Synchronization is built in; naturally distributable; per-message copy/kernel cost.
Pipes
Anonymous: unidirectional byte stream between related processes (`ls | grep`). Named (FIFO): has a filesystem name, so unrelated processes can use it.
Sockets
Bidirectional; TCP (reliable stream) or UDP (unreliable datagrams); the only mechanism that crosses machine boundaries. Unix domain sockets for fast local IPC.
Signals
Asynchronous notifications — which signal was sent, little else. Good for control, not data. SIGKILL/SIGSTOP cannot be caught.

Example

// Anonymous pipe: connect stdout of a child to a parent
int fd[2]; pipe(fd);            // fd[0] = read end, fd[1] = write end
if (fork() == 0) {             // child
    close(fd[0]);
    dup2(fd[1], STDOUT_FILENO); // child's stdout → pipe
    execlp("ls", "ls", NULL);
}
close(fd[1]);
// parent reads the child's output from fd[0]; read() returns 0 (EOF) when
// all write ends are closed.
Common exam traps

Anonymous pipes only connect processes with a common ancestor. Writing to a pipe whose read end is closed raises SIGPIPE. Shared memory is fastest but you own the synchronization; message passing has it built in. Only sockets cross machine boundaries. System V IPC objects persist until explicitly removed (leak risk).

Practice MCQs

Q1. The two fundamental IPC models are:

  1. files and pipes
  2. shared memory and message passing
  3. signals and sockets
  4. threads and processes
Show answer

Answer: B. Fast-but-manual vs safe-but-copied.

Q2. A pipe provides:

  1. random access
  2. a unidirectional byte stream between related processes
  3. shared memory
  4. a priority message queue
Show answer

Answer: B. `ls | grep` connects a parent and child.

Q3. Which IPC crosses machine boundaries?

  1. shared memory
  2. sockets (TCP/UDP)
  3. anonymous pipes
  4. signals
Show answer

Answer: B. Only network sockets (or RPC over them).

Q4. When all write ends of a pipe are closed, a read() returns:

  1. an error
  2. 0 (end-of-file)
  3. the last byte forever
  4. SIGPIPE
Show answer

Answer: B. EOF tells the reader no more data will come.

Q5. The main drawback of signals for IPC is:

  1. too much data
  2. very limited information and standard signals are not queued
  3. they are slow
  4. they need root
Show answer

Answer: B. Good for control, not data transfer.
