Concurrency & Synchronization

When concurrent threads/processes share data, synchronization ensures the result is correct (equivalent to some valid serial order) without needlessly limiting parallelism. The critical-section problem demands mutual exclusion, progress and bounded waiting.

Key points

Critical section
Code that accesses shared data and must run one-at-a-time. Protected by mutexes, semaphores or monitors.
Semaphore
wait()/P decrements (blocks if it would go negative); signal()/V increments (wakes a waiter). Counting (N resources) or binary (lock/signal).
Mutex vs semaphore
A mutex has ownership (only the locker unlocks) and often priority inheritance; a semaphore is for signalling / counting and any thread can signal it.
Monitor + condition variable
A module with automatic mutual exclusion; a condition variable lets a thread wait (releasing the lock) until a predicate holds. Always re-check in a while loop (spurious wakeups).
Classic problems
Producer-consumer (bounded buffer: mutex + empty + full semaphores), readers-writers, dining philosophers (deadlock/starvation).

Diagram

Example

// Producer                         // Consumer
wait(empty);   // slots available     wait(full);    // items available
wait(mutex);                          wait(mutex);
  buffer[in] = item; in = (in+1)%N;     item = buffer[out]; out = (out+1)%N;
signal(mutex);                        signal(mutex);
signal(full);  // one more item       signal(empty); // one more slot

// If the producer does wait(mutex) BEFORE wait(empty): DEADLOCK when full.
Common exam traps

Always acquire resource semaphores (empty/full) BEFORE the mutex, or you deadlock. Re-check a condition variable's predicate in a `while`, not an `if` (spurious wakeups, signal-and-continue). A binary semaphore is not a mutex — no ownership. Disabling interrupts only works on a single core. Reader-priority readers-writers starves writers.

Practice MCQs

Q1. The critical-section problem requires:

  1. speed, size, simplicity
  2. mutual exclusion, progress, and bounded waiting
  3. fairness only
  4. determinism
Show answer

Answer: B. One at a time; no indefinite postponement; no starvation.

Q2. A counting semaphore with value S:

  1. allows S threads through wait() before blocking
  2. allows only 1 thread ever
  3. is identical to a mutex
  4. cannot go below 0
Show answer

Answer: A. V() increments; a negative internal count means waiters are queued.

Q3. In the bounded-buffer solution the semaphores are:

  1. one mutex only
  2. mutex (=1), empty (=N), full (=0)
  3. three mutexes
  4. two turn variables
Show answer

Answer: B. empty/full block the producer/consumer; mutex protects the buffer.

Q4. A condition variable must be used with:

  1. another condition variable
  2. a mutex
  3. a semaphore
  4. a spinlock only
Show answer

Answer: B. wait() atomically releases the mutex and sleeps.

Q5. The dining philosophers problem illustrates:

  1. scheduling
  2. deadlock and starvation in resource allocation
  3. paging
  4. file systems
Show answer

Answer: B. 5 philosophers need 2 adjacent forks each.
