Business & Service Scalability, Reliability

Scalability is the ability to handle growing load; reliability is the ability to keep working correctly despite failure. They're achieved together through the same toolkit — redundancy, load balancing, automation, and honest measurement (SLAs, SLOs, SLIs).

Key points

Vertical vs horizontal scaling
Vertical = bigger machine (limited ceiling). Horizontal = more machines behind a load balancer (needs stateless/externalized-state design).
Elasticity
Scaling automatically both UP and DOWN with demand — distinct from scalability, which just means "can handle more, given more resources".
Redundancy · fault tolerance · failover
Duplicate components remove single points of failure; a fault-tolerant system keeps working despite a failed part; failover is the standby taking over automatically.
SLA / SLO / SLI
SLI = the measured metric. SLO = the internal target for that metric. SLA = the external, often contractual, promise built on it.
MTBF / MTTR
Mean Time Between Failures (bigger is better) and Mean Time To Repair (smaller is better) — together they drive overall availability.

Diagram

Example

A service sets an SLO: "99.9% of requests succeed in under 300ms, per month."
  - SLI (measured this month): 99.95% of requests met that target.
  - Result: SLO met, with an "error budget" of 0.1% still unspent this month.
  - The SLA (external promise to customers) is set more conservatively at 99.5%,
    with service credits owed if it is missed.

Reliability math: if MTBF = 720 hours and MTTR = 1 hour,
  Availability ~= MTBF / (MTBF + MTTR) = 720 / 721 ~= 99.86%
Adding a second, redundant instance (N+1) removes this as a single point of
failure — failover can restore service in seconds instead of the full MTTR.
Common exam traps

SLI = measured value, SLO = internal target, SLA = external contractual promise — questions often swap these. Elasticity ≠ scalability: elasticity specifically means scaling back DOWN automatically too, not just up. Horizontal scaling generally requires a stateless (or externalized-state) application tier; a service that stores session data only in one instance's memory cannot simply be load-balanced across many instances.

Practice MCQs

Q1. Horizontal scaling means:

  1. Upgrading a single server's CPU/RAM
  2. Adding more machines/instances to share the load
  3. Reducing the number of servers
  4. Only applies to storage, never compute
Show answer

Answer: B. Upgrading one machine's hardware is vertical scaling instead.

Q2. An SLI (Service Level Indicator) is:

  1. A legal contract with customers
  2. The actual measured metric used to judge whether an SLO is being met
  3. Identical to an SLA
  4. Only relevant to hardware procurement
Show answer

Answer: B. SLOs are the internal target for that measured value; SLAs are the external promise built on it.

Q3. "N+1" redundancy means:

  1. Exactly N components with no spare capacity
  2. N components needed for normal load, plus one spare so one failure causes no impact
  3. N times the necessary capacity for no clear reason
  4. A single component with zero redundancy
Show answer

Answer: B. "2N" (a fully duplicated set) provides even more tolerance, at higher cost.

Q4. A circuit breaker pattern in a distributed system:

  1. Permanently disables a service after its first failure
  2. Stops sending requests to a consistently failing dependency, letting it recover and preventing cascading failure
  3. Increases load sent to a struggling dependency
  4. Physically cuts power to a server
Show answer

Answer: B. This is a common resilience pattern to stop one failing dependency from bringing down others.

Q5. Elasticity, as distinct from plain scalability, specifically emphasizes:

  1. The maximum theoretical capacity a system could ever reach
  2. Automatically scaling both up AND back down with demand, avoiding paying for unused capacity
  3. That scaling must always be manual
  4. That resources, once added, can never be removed
Show answer

Answer: B. A system can be scalable without being elastic if it never automatically scales back down.
