Flow & Error Control

Flow control keeps a fast sender from overwhelming a slow receiver. Error control detects (and sometimes corrects) bits damaged in transit. Together they are what makes an unreliable physical link usable for reliable communication.

Key points

Stop-and-wait
Send one frame, wait for its ACK, then send the next. Simple but wastes the link during the round-trip wait.
Sliding window (Go-Back-N / Selective Repeat)
Pipeline multiple unacknowledged frames. Go-Back-N resends everything after a lost frame; Selective Repeat resends only the lost frame(s) but needs more receiver buffering.
Parity / Checksum / CRC
Increasing detection strength: 1 parity bit (weak) → Internet checksum (moderate) → CRC (strong, catches burst errors — used in Ethernet's FCS).
Hamming code
Adds enough redundant bits to both detect AND correct single-bit errors.
ARQ vs FEC
ARQ (Automatic Repeat reQuest) retransmits on error — needs a return channel. FEC (Forward Error Correction) sends enough redundancy to fix errors with no retransmission — vital for one-way/real-time links.

Diagram

Example

Go-Back-N with window size 4, sending frames 0..3:

Sent:      0  1  2  3
Arrived:   OK OK LOST OK
Receiver:  accepts 0, 1; DISCARDS 3 (out of order, expects 2); no ACK for 3

Sender times out waiting for ACK 2, and must retransmit
frames 2 AND 3 (even though 3 already arrived once) --
this is Go-Back-N's core inefficiency vs Selective Repeat,
which would buffer frame 3 and ask only for frame 2 again.
Common exam traps

Flow control protects the RECEIVER; congestion control (a separate topic) protects the NETWORK. A single parity bit detects only an ODD number of bit flips and cannot correct anything. CRC is much stronger than a simple checksum. To correct t errors, minimum Hamming distance must be ≥ 2t+1; to merely detect d errors, distance ≥ d+1. FEC needs no retransmission; ARQ does.

Practice MCQs

Q1. Flow control exists to:

  1. Detect bit errors
  2. Prevent a fast sender from overwhelming a slow receiver
  3. Route packets
  4. Assign IP addresses
Show answer

Answer: B. It matches sender rate to what the receiver can actually buffer/process.

Q2. In Go-Back-N, if frame 3 of a 4-frame window is lost, the sender:

  1. Retransmits only frame 3
  2. Retransmits frame 3 and every frame after it in the window
  3. Aborts the connection
  4. Ignores the loss
Show answer

Answer: B. The receiver discards out-of-order frames, forcing a full resend from the gap onward.

Q3. CRC (Cyclic Redundancy Check) is used for:

  1. Encryption
  2. Strong error detection, catching most burst errors
  3. Flow control
  4. Routing
Show answer

Answer: B. Used in Ethernet's FCS trailer.

Q4. Hamming code can:

  1. Only detect errors, never correct them
  2. Detect and correct single-bit errors
  3. Only work on ASCII text
  4. Replace CRC entirely
Show answer

Answer: B. A minimum Hamming distance of 3 enables single-bit correction.

Q5. FEC differs from ARQ in that FEC:

  1. Requires a return channel for retransmission requests
  2. Adds enough redundancy for the receiver to correct errors without retransmission
  3. Cannot be used in real-time applications
  4. Only works for text
Show answer

Answer: B. Valuable when retransmission is slow, costly, or impossible.
