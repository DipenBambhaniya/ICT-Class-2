Arrays

An array stores elements of one type in a single contiguous block. Address arithmetic (base + i·size) gives O(1) random access and excellent cache locality; the price is a fixed size and O(n) insert/delete in the middle.

Key points

Random access
a[i] = *(base + i) — constant time regardless of i.
Insert / delete (ordered)
O(n): elements after the position must shift.
Dynamic array
Doubles capacity when full ⇒ amortized O(1) append.
2D layout
C is row-major: a[i][j] at offset i*ncols + j.
Cache locality
Sequential (stride-1) traversal is far faster than pointer chasing or random access.

Diagram

Example

int a[6] = {17, 4, 42, 8, 23, 16};
int sum = 0;
for (int i = 0; i < 6; i++) sum += a[i];   /* O(n) scan */

/* Kadane: max contiguous subarray sum in O(n) */
int best = a[0], cur = a[0];
for (int i = 1; i < 6; i++) { cur = (cur > 0 ? cur : 0) + a[i]; best = cur > best ? cur : best; }
Common exam traps

sizeof(a)/sizeof(a[0]) gives the length only before the array decays to a pointer (i.e. not inside a function that received it). C does no bounds checking. Inserting at the front is O(n); appending to a doubling dynamic array is amortized O(1), not O(1) worst case.

Practice MCQs

Q1. Accessing a[i] takes:

  1. O(n)
  2. O(log n)
  3. O(1)
  4. O(i)
Show answer

Answer: C. base + i*size is a constant-time calculation.

Q2. Inserting at the beginning of an n-element array takes:

  1. O(1)
  2. O(log n)
  3. O(n)
  4. O(n log n)
Show answer

Answer: C. Every existing element shifts right by one.

Q3. A dynamic array gets amortized O(1) append by:

  1. never resizing
  2. doubling capacity when full
  3. using a linked list
  4. adding one slot each time
Show answer

Answer: B. Geometric growth spreads copy cost so the average append is O(1).

Q4. int a[3][4] in C is stored:

  1. column-major
  2. row-major
  3. as 3 pointers
  4. randomly
Show answer

Answer: B. Row 0 fully, then row 1, ... offset = i*4 + j.

Q5. Binary search requires the array to be:

  1. unsorted
  2. sorted
  3. of even length
  4. on the heap
Show answer

Answer: B. Ordering lets each step discard half the range — O(log n).
