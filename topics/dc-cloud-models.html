Public, Private & Hybrid Cloud

Where should a workload actually run? Public, private and hybrid cloud are deployment models answering "who owns/shares the infrastructure"; IaaS, PaaS and SaaS are service models answering "how much of the stack does the provider manage for you". Real strategy usually mixes both decisions per workload.

Key points

Public cloud
Multi-tenant infrastructure owned by a third party (AWS, Azure, GCP) — low upfront cost, high elasticity.
Private cloud
Cloud-style self-service/elasticity on infrastructure dedicated to one organization (on-premises or hosted) — more control, more management burden.
Hybrid cloud
Public + private (or on-premises) integrated together — e.g. sensitive data stays private while a public front-end absorbs traffic spikes ("cloud bursting").
Community cloud
Shared by several organizations with common compliance/mission needs (e.g. several government agencies).
IaaS · PaaS · SaaS
Increasing provider responsibility, decreasing customer responsibility: IaaS (raw VMs/storage/network) → PaaS (+ OS/runtime) → SaaS (a finished application).

Diagram

Example

An online retailer:
  - Keeps its financial/inventory database on PRIVATE infrastructure
    (compliance, full control) — an IaaS-style deployment it manages itself.
  - Runs its customer-facing storefront on PUBLIC cloud, auto-scaling to
    absorb Diwali/holiday-sale traffic spikes ("cloud bursting").
  - Uses a SaaS email-marketing tool with no infrastructure of its own.

Together: a HYBRID cloud strategy, mixing IaaS (private DB), IaaS/PaaS
(public storefront) and SaaS (email tool) — each workload placed where its
cost, control and scalability needs are best met.
Common exam traps

"Multi-cloud" (several public providers) is not the same as "hybrid cloud" (public + private/on-premises integrated). Public cloud shifts spend from CapEx to OpEx. IaaS gives the customer the MOST management responsibility (OS upward); SaaS gives the LEAST. The "shared responsibility model" means the provider secures the underlying platform while the customer must correctly configure what they deploy on it.

Practice MCQs

Q1. A hybrid cloud is best described as:

  1. Two public cloud providers used together, nothing private
  2. An integration of public and private (or on-premises) infrastructure, letting workloads move between them
  3. Infrastructure available only inside one building
  4. A single vendor's infrastructure exclusively
Show answer

Answer: B. Using several public providers together (with no private component) is "multi-cloud", a different concept.

Q2. Which service model leaves the customer managing the OS and everything above it?

  1. SaaS
  2. PaaS
  3. IaaS
  4. None — the provider always manages the OS
Show answer

Answer: C. IaaS gives the customer virtualized infrastructure only; PaaS additionally manages the OS/runtime; SaaS manages everything.

Q3. "Cloud bursting" refers to:

  1. Permanently moving all workloads to the public cloud
  2. An app normally running privately automatically expanding into public cloud during demand spikes
  3. Deleting excess cloud resources
  4. A type of network attack
Show answer

Answer: B. This avoids over-provisioning private infrastructure just for occasional peaks.

Q4. A regulated organization required to keep data within national borders would most likely favor:

  1. Any public cloud region, without restriction
  2. A private cloud, or a public/hybrid deployment configured for that specific data residency requirement
  3. Avoiding digital storage entirely
  4. Storing data wherever is cheapest
Show answer

Answer: B. Data residency/compliance needs are a classic driver toward private or carefully-configured hybrid deployments.

Q5. The "shared responsibility model" in cloud security means:

  1. The provider is responsible for absolutely everything, including customer data
  2. The provider secures the underlying platform; the customer must correctly configure/secure what they deploy on it
  3. Only the customer bears any security responsibility
  4. It applies only to private cloud
Show answer

Answer: B. Exactly where the line falls shifts with the service model — SaaS shifts more responsibility to the provider than IaaS does.
