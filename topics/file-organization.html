File Organization

File organization describes how a relation's records are physically arranged into disk blocks. The choice fixes the cost of insert, delete, equality search and range search — because the dominant cost in a DBMS is block (page) I/O, not CPU.

Key terms

Block / page
The fixed-size unit transferred between disk and memory (e.g. 4 KB). All cost is counted in block accesses.
Blocking factor (bfr)
Number of records that fit in one block = ⌊block size / record size⌋.
Spanned vs unspanned
Spanned: a record may cross a block boundary. Unspanned: each record lies wholly inside one block (wastes the leftover bytes).
Ordering field / key
The attribute a sequential file is physically sorted on. If it is also unique it is the ordering key.

Example — blocking factor

Block size      = 4096 bytes
Record size     = 200 bytes
Number of rows  = 30000

Blocking factor bfr = floor(4096 / 200) = 20 records/block
Blocks needed  b    = ceil(30000 / 20)  = 1500 blocks

Heap  equality search (avg) = b / 2   = 750 block reads
Sorted equality search      = log2(1500) ≈ 11 block reads
Common exam traps

Hashing gives near-constant lookup only for the exact hash field with an equality predicate — it is useless for BETWEEN / ORDER BY / < ranges. A heap file has the cheapest insertion but the most expensive search. "Sequential file" means physically sorted on disk — not merely "read one record after another".

Practice MCQs

Q1. In which file organization is a new record simply inserted at the end of the file?

  1. Sequential (ordered) file
  2. Heap (pile / unordered) file
  3. Hash file
  4. B+ tree file
Show answer

Answer: B — Heap file. Records are placed in insertion order at the end of the last block, making insertion O(1) but forcing a linear scan for retrieval.

Q2. Hash file organization performs worst for which type of query?

  1. Equality search on the hash field
  2. Range search (e.g. salary BETWEEN 30000 AND 50000)
  3. Single-record insertion
  4. Primary-key point lookup
Show answer

Answer: B. A hash function scatters keys across buckets with no order relationship, so a range query must scan every bucket — hashing only helps exact-match lookups.

Q3. The number of records that can be stored in one disk block is called the:

  1. Fill factor
  2. Blocking factor
  3. Fan-out
  4. Selectivity
Show answer

Answer: B — Blocking factor (bfr) = ⌊block size ÷ record size⌋ for fixed-length unspanned records.

Q4. A file organization where records that are frequently accessed together (often from different relations) are physically stored in the same blocks is called:

  1. Heap organization
  2. Clustered (clustering) organization
  3. Hash organization
  4. Spanned organization
Show answer

Answer: B. Clustering stores related rows together so a join or a multi-row lookup on the clustering key needs far fewer block reads.

Q5. With b sorted blocks, the number of block accesses for a binary search on the ordering key is approximately:

  1. b
  2. b / 2
  3. log₂ b
  4. 1
Show answer

Answer: C — log₂ b. Because the blocks are physically ordered on the search key, binary search halves the range each step.

Q6. "Unspanned" record organization means:

  1. A record may be split across two blocks
  2. Every record is stored entirely within a single block
  3. Records are stored without any blocking
  4. Records are compressed before storage
Show answer

Answer: B. Unspanned means no record crosses a block boundary; leftover bytes at the end of a block are wasted. Spanned organization allows a record to continue into the next block.
