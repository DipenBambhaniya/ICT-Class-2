Advanced SQL

CTEs, window functions, advanced joins, and GROUPING SETS/CUBE/ROLLUP are the practical SQL tools that implement OLAP-style analysis, dimensional queries, and in-database analytics directly in standard SQL.

Key points

CTEs (WITH clause)
Named, temporary result sets for one statement — improves readability over nested subqueries. A RECURSIVE CTE traverses hierarchies (org charts, bill of materials).
Window functions
Compute a value (rank, running total, LAG/LEAD) per row WITHOUT collapsing rows — unlike GROUP BY. PARTITION BY resets the calculation per group; ORDER BY inside OVER() drives running/cumulative behavior.
RANK vs DENSE_RANK vs ROW_NUMBER
ROW_NUMBER: always unique, sequential. RANK: ties share a rank, next rank SKIPS. DENSE_RANK: ties share a rank, no gap follows.
Joins
INNER JOIN: only matching rows. LEFT JOIN: all left-table rows, NULLs for no match — essential for "include zero/none" reporting.
GROUPING SETS / CUBE / ROLLUP
Compute multiple GROUP BY aggregation levels in a single query — the SQL implementation of the data-cube "multiple cuboids" concept.

Example

-- Rank each employee's salary within their own department
SELECT name, department, salary,
       RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS dept_rank
FROM employees;

-- Recursive CTE: all reports under a manager, any depth
WITH RECURSIVE org AS (
  SELECT employee_id, manager_id, name FROM employees WHERE manager_id = 1
  UNION ALL
  SELECT e.employee_id, e.manager_id, e.name
  FROM employees e JOIN org ON e.manager_id = org.employee_id
)
SELECT * FROM org;

-- Include customers with ZERO orders
SELECT c.name, COALESCE(SUM(o.amount), 0) AS total
FROM customers c LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.name;
Common exam traps

Window functions do NOT collapse rows like GROUP BY — that's their defining difference. RANK() skips numbers after a tie; DENSE_RANK() doesn't. HAVING filters AFTER aggregation; WHERE filters BEFORE. Use LEFT JOIN (not INNER JOIN) to include rows with no match — pair it with COALESCE() to turn resulting NULL aggregates into 0.

Practice MCQs

Q1. A Common Table Expression (CTE) is used to:

  1. Permanently store a table in the schema
  2. Define a named, temporary result set for one statement
  3. Replace the need for any JOIN
  4. Encrypt query results
Show answer

Answer: B. Improves readability over deeply nested subqueries.

Q2. A window function differs from GROUP BY in that it:

  1. Always collapses rows into one summary row
  2. Computes a value per row while still returning all individual rows
  3. Cannot be used with ORDER BY
  4. Can only be used in WHERE
Show answer

Answer: B. This is the key distinguishing feature.

Q3. RANK() differs from ROW_NUMBER() in that RANK():

  1. Never allows ties
  2. Gives tied rows the same rank and skips the next rank number(s)
  3. Is identical to ROW_NUMBER()
  4. Cannot use PARTITION BY
Show answer

Answer: B. DENSE_RANK() gives the same rank but does NOT skip.

Q4. HAVING differs from WHERE in that HAVING:

  1. Filters rows before aggregation, exactly like WHERE
  2. Filters groups/aggregated results after GROUP BY is applied
  3. Is interchangeable with WHERE in every case
  4. Can only be used without GROUP BY
Show answer

Answer: B. You can't filter on an aggregate using WHERE alone.

Q5. To list ALL customers including those with zero orders, you should use:

  1. An INNER JOIN
  2. A LEFT JOIN from customers to orders
  3. A RIGHT JOIN from orders to customers only
  4. No join at all
Show answer

Answer: B. INNER JOIN would incorrectly exclude customers with no matching order.
