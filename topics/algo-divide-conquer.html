Divide & Conquer

Divide the problem into smaller independent subproblems, solve each recursively, then combine. The recurrence T(n) = aT(n/b) + f(n) captures the cost; the master theorem solves it.

Key points

Three steps
Divide → conquer (recurse) → combine.
Master theorem
Compare f(n) with n^(log_b a): smaller ⇒ Θ(n^(log_b a)); equal ⇒ Θ(n^(log_b a) log n); larger ⇒ Θ(f(n)).
Merge sort
T(n) = 2T(n/2) + O(n) ⇒ Θ(n log n). Binary search: T(n) = T(n/2) + O(1) ⇒ Θ(log n).
Fast multiplication
Karatsuba T(n) = 3T(n/2) + O(n) ⇒ n^1.585; Strassen 7T(n/2) + O(n²) ⇒ n^2.807.
vs Dynamic programming
D&C suits DISJOINT subproblems; overlapping subproblems need memoization (DP).

Diagram

Example

mergeSort(A):
    if len(A) <= 1: return A
    mid = len(A) / 2
    L = mergeSort(A[:mid]);  R = mergeSort(A[mid:])   // divide + conquer
    return merge(L, R)                                 // combine, O(n)

// Master theorem: a=2, b=2, f(n)=n = n^(log2 2) ⇒ Θ(n log n)
Common exam traps

T(n)=2T(n/2)+O(1) is Θ(n), not Θ(log n) (that's ONE-branch recursion). Binary search recurses into only one half. Pre + post traversal cannot uniquely rebuild a general binary tree. Naive recursive Fibonacci is D&C-shaped but exponential because subproblems overlap — that needs DP.

Practice MCQs

Q1. The three steps of divide and conquer are:

  1. sort, search, merge
  2. divide, conquer (recurse), combine
  3. guess, check, repeat
  4. hash, probe, resize
Show answer

Answer: B. Split, solve recursively, merge.

Q2. Binary search's recurrence is:

  1. T(n)=2T(n/2)+O(1)
  2. T(n)=T(n/2)+O(1)
  3. T(n)=T(n/2)+O(n)
  4. T(n)=2T(n/2)+O(n)
Show answer

Answer: B. It recurses into ONE half with constant work => O(log n).

Q3. T(n) = 2T(n/2) + O(n^2) solves to:

  1. O(n^2)
  2. O(n^2 log n)
  3. O(n log n)
  4. O(n^3)
Show answer

Answer: A. Master case 3: f(n)=n^2 dominates n.

Q4. Karatsuba multiplication T(n) = 3T(n/2) + O(n) gives:

  1. O(n^2)
  2. O(n^1.585)
  3. O(n log n)
  4. O(n^3)
Show answer

Answer: B. n^(log2 3) ~ n^1.585.

Q5. D&C is preferred over DP when subproblems are:

  1. heavily overlapping
  2. disjoint / independent
  3. on a graph
  4. sorted
Show answer

Answer: B. Overlap calls for memoization.
