Integrity Constraints

Integrity constraints are rules a relational DBMS enforces automatically so that the data in the database always stays accurate, valid and consistent — no matter what insert, update or delete an application attempts.

The main types

Domain constraint
Every attribute value must be an atomic value drawn from its declared domain (data type, size, format). Enforced by column type plus NOT NULL, CHECK, and DEFAULT.
Entity integrity constraint
No attribute of a primary key may be NULL, and the primary key value must be unique. This guarantees every tuple (row) is individually identifiable.
Key constraint
Every candidate key must hold unique values across all rows — declared with PRIMARY KEY or UNIQUE.
Referential integrity constraint
A foreign key value in the child table must either match some existing primary key value in the parent table, or be entirely NULL. It stops "dangling" references.
General / semantic constraints (assertions & triggers)
Business rules that span rows or tables, e.g. "an account balance can never go below zero" — expressed via CHECK, ASSERTION, or a trigger.

Example — declaring constraints in SQL

CREATE TABLE Department (
    Dept_ID    INT        PRIMARY KEY,              -- entity integrity + key
    Dept_Name  VARCHAR(40) NOT NULL UNIQUE          -- domain + key
);

CREATE TABLE Employee (
    Emp_ID   INT         PRIMARY KEY,
    Name     VARCHAR(50) NOT NULL,                  -- domain constraint
    Salary   DECIMAL(9,2) CHECK (Salary > 0),      -- semantic constraint
    Dept_ID  INT,
    FOREIGN KEY (Dept_ID) REFERENCES Department(Dept_ID)
        ON DELETE SET NULL                          -- referential action
        ON UPDATE CASCADE
);

Referential actions decide what happens to child rows when a referenced parent row changes:

ActionOn delete / update of parent key
CASCADEAutomatically delete / update the matching child rows too
SET NULLSet the foreign key in child rows to NULL
SET DEFAULTSet the foreign key to its declared default value
RESTRICT / NO ACTIONReject the operation if any child row still references the parent
Common exam traps

Entity integrity = primary key attributes cannot be NULL. Referential integrity = foreign key must match an existing primary key (or be NULL). Students often swap these two. Also: a foreign key can be NULL unless it is also declared NOT NULL; and it may reference a UNIQUE column, not only a primary key.

Practice MCQs

Q1. The rule "no primary key attribute value may be NULL" is called:

  1. Referential integrity
  2. Entity integrity
  3. Domain integrity
  4. Key integrity
Show answer

Answer: B — Entity integrity. It ensures every tuple can be uniquely identified; a NULL in any part of the primary key would break that identification, so it is forbidden.

Q2. A foreign key value that does not match any primary key value in the referenced relation violates:

  1. Entity integrity
  2. Domain constraint
  3. Referential integrity
  4. Tuple ordering
Show answer

Answer: C — Referential integrity. The foreign key must either be NULL or equal to an existing primary key value in the parent table; a "dangling" reference is rejected.

Q3. CHECK (Age >= 18) on a column is an example of a:

  1. Referential constraint
  2. Domain / semantic constraint
  3. Entity constraint
  4. Candidate key constraint
Show answer

Answer: B. A CHECK restricts the set of allowed values for an attribute, i.e. it narrows the column's domain, so it is a domain (semantic) constraint.

Q4. With ON DELETE CASCADE defined on the Employee→Department foreign key, deleting a department will:

  1. Be rejected because employees still reference it
  2. Set the employees' Dept_ID to NULL
  3. Automatically delete all employees in that department
  4. Delete the department but leave orphaned employee rows
Show answer

Answer: C. CASCADE propagates the delete to matching child rows, so all employees of that department are removed automatically, keeping referential integrity intact.

Q5. Which statement about a foreign key is TRUE?

  1. It must always be part of the primary key of its own table
  2. It can be NULL unless additionally declared NOT NULL
  3. It can never reference a column in the same table
  4. It must reference a non-unique column
Show answer

Answer: B. A foreign key may hold NULL (meaning "no relationship") unless a NOT NULL constraint is added. Self-referencing foreign keys (e.g. Employee.Manager_ID → Employee.Emp_ID) are allowed, and the referenced column must be a key (PRIMARY KEY or UNIQUE).

Q6. Constraints that cannot be expressed on a single table and instead express a condition over the whole database are declared using:

  1. NOT NULL
  2. PRIMARY KEY
  3. An assertion (or a trigger)
  4. A DEFAULT clause
Show answer

Answer: C. An ASSERTION defines a global predicate the whole database must satisfy; where assertions are unsupported, triggers are used to enforce the same multi-table business rule.
